= Standalone CLI
:description: `chappe serve` — serves a static site without a Java launcher.

[.lead]
The `chappe-cli` module provides the `chappe serve` subcommand: configuration via
YAML file or flags, self-contained fat jar, minimal jlink image for Docker. Zero
dependencies beyond the JDK — the in-house YAML parser, config merge, and
compression negotiation all live in `chappe-cli/`.

== Build and run

[source,bash]
----
mvn -ntp -pl chappe-cli -am package
java --enable-preview -jar chappe-cli/target/chappe-cli-*-shaded.jar \
     serve --root /var/www/site --port 8080 --gzip
----

Or via the wrapper script:

[source,bash]
----
export CHAPPE_HOME=/opt/chappe
chappe serve --config /etc/chappe/config.yml
----

== YAML configuration

Documented subset: nested maps, inline `[a, b]` and block `- item` lists, string/int/bool
scalars, `#` comments. No anchors, `!!` tags, or multilines.

[source,yaml]
----
server:
  port: 8080
  bind: 0.0.0.0

static:
  root: /var/www/site
  fallback: /404.html              # served with status 404
  spa-fallback: /index.html        # mutually exclusive (SPA mode, status 200)
  index-files: [index.html]
  cache-control: "max-age=3600, public"
  gzip: true                        # negotiated via Accept-Encoding

headers:
  always:                           # injected on every response
    X-Content-Type-Options: "nosniff"
    Referrer-Policy: "strict-origin-when-cross-origin"
  staging:                          # active when env var STAGING=true
    X-Robots-Tag: "noindex, nofollow"

logging:
  level: INFO
  access-log: false
----

== CLI flags

Set flags take precedence over YAML values.

[cols="1,3"]
|===
| Flag | Effect

| `--config FILE`         | load a YAML file
| `--root DIR`            | override `static.root`
| `--port N`              | override `server.port` (default 8080)
| `--bind ADDR`           | override `server.bind` (default 0.0.0.0)
| `--fallback PATH`       | override `static.fallback` (status 404)
| `--spa-fallback PATH`   | enable SPA mode (status 200 on 404)
| `--cache-control STR`   | override `static.cache-control`
| `--gzip` / `--no-gzip`  | enable/disable compression
| `--header KEY=VALUE`    | add a header (repeatable, merged into `headers.always`)
| `-h, --help`            | help
|===

== Compression

With `--gzip` (or `static.gzip: true`):

* serves precompressed `.br` / `.gz` sidecars when present (zero-copy via `FileChannel.transferTo`),
* otherwise compresses on the fly for text-like `Content-Type` > 1 KB, emitting
  `Content-Encoding: gzip` and `Vary: Accept-Encoding`,
* automatic skip when `Cache-Control: no-transform` or `Content-Encoding` is already set.

Brotli is not generated at runtime (the JDK 25 has no Brotli encoder), but
`.br` sidecars produced by a build pipeline are served when the client sends
`Accept-Encoding: br`. To generate `.gz` at build time:

[source,xml]
----
<plugin>
  <groupId>io.vidocq.chappe</groupId>
  <artifactId>chappe-static-index-maven-plugin</artifactId>
  <executions>
    <execution>
      <goals><goal>index</goal></goals>
      <configuration><compress>gzip</compress></configuration>
    </execution>
  </executions>
</plugin>
----

== Conditional headers

`headers.staging` is applied only when the `STAGING` environment variable equals
exactly `true`. From the API, see `Filter.addHeaderIfEnv`:

[source,java]
----
Router.builder()
    .filter(Filter.addHeader("X-Content-Type-Options", "nosniff"))
    .filter(Filter.addHeaderIfEnv("STAGING", "true",
            "X-Robots-Tag", "noindex, nofollow"))
    .build();
----

== Docker

=== Fat-jar image

[source,dockerfile]
----
FROM eclipse-temurin:25-jre AS runtime
COPY chappe-cli/target/chappe-cli-*-shaded.jar /opt/chappe/lib/chappe-cli-shaded.jar
COPY chappe-cli/src/main/scripts/chappe         /opt/chappe/bin/chappe
ENV PATH=/opt/chappe/bin:$PATH CHAPPE_HOME=/opt/chappe
COPY site/      /var/www/site
COPY config.yml /etc/chappe/config.yml
EXPOSE 8080
ENTRYPOINT ["chappe", "serve", "--config", "/etc/chappe/config.yml"]
----

=== jlink image (~50 MB)

[source,bash]
----
jlink \
  --module-path "chappe-cli/target:$JAVA_HOME/jmods" \
  --add-modules io.vidocq.chappe.cli,jdk.crypto.ec,jdk.localedata \
  --launcher chappe=io.vidocq.chappe.cli/io.vidocq.chappe.cli.Main \
  --enable-preview --strip-debug --no-man-pages --no-header-files \
  --output target/chappe-runtime
----

[source,dockerfile]
----
FROM debian:bookworm-slim
COPY target/chappe-runtime /opt/chappe
ENV PATH=/opt/chappe/bin:$PATH
COPY site/ /var/www/site
ENTRYPOINT ["chappe", "serve", "--root", "/var/www/site"]
----

== Limitations

* TLS not handled by the CLI — place behind a reverse proxy (nginx, Caddy) or use a programmatic launcher.
* No config hot reload — a change requires a restart.
* Runtime Brotli not produced (only `.br` sidecars are served).
* Mini-YAML: no multilines or anchors. For complex configs, write a Java launcher.
