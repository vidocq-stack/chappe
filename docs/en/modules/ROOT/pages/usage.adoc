= Usage
:description: TLS, HTTP/2, HTTP/3 (planned), gzip, virtual hosts, static files, standalone CLI.

[.lead]
This page collects the operational recipes: terminating TLS, negotiating HTTP/2 via ALPN, mounting several sub-applications, serving static files with zero-copy, negotiating compression, and running the `chappe serve` CLI to ship a site without a Java launcher.

== TLS / HTTPS

Chappe uses the JDK's `SSLContext`/`SSLEngine` directly. No wrapper, no reimplementation.

[source,java]
----
import javax.net.ssl.SSLContext;
import io.vidocq.chappe.api.*;

SSLContext sslContext = ...;   // loaded from a JKS / PKCS12 keystore

try (var server = Server.builder()
        .port(8443)
        .tls(sslContext)
        .alpnProtocols("h2", "http/1.1")
        .handler(router)
        .build()) {
    server.start();
    Thread.currentThread().join();
}
----

Key points:

* `alpnProtocols("h2", "http/1.1")` advertises both protocols via ALPN; HTTP/2 is selected when the client offers it.
* TLS 1.3 and TLS 1.2 are supported (standard `SSLContext` policy).
* Certificate and key are loaded from a JDK keystore (`KeyStore.getInstance("PKCS12")`). No native PEM loader on the Chappe side.

[#client-certificates]
=== Client certificates [.tag-new]#NEW#

A TLS listener can ask clients for a certificate. Pass a `ClientAuth` mode with the context; the context's trust managers decide which certificates are accepted, so build it with a `TrustManagerFactory` over the certificates or CAs you trust:

[source,java]
----
import java.security.KeyStore;
import javax.net.ssl.*;
import io.vidocq.chappe.api.*;

KeyStore serverKeys = ...;      // the server's key pair (PKCS12)
KeyStore trustedClients = ...;  // the client certificates or CAs you accept

var kmf = KeyManagerFactory.getInstance(KeyManagerFactory.getDefaultAlgorithm());
kmf.init(serverKeys, password);
var tmf = TrustManagerFactory.getInstance(TrustManagerFactory.getDefaultAlgorithm());
tmf.init(trustedClients);
var sslContext = SSLContext.getInstance("TLS");
sslContext.init(kmf.getKeyManagers(), tmf.getTrustManagers(), null);

Server.builder()
        .port(8443)
        .tls(sslContext, ClientAuth.WANT)
        .handler(req -> req.tls()
                .filter(tls -> !tls.peerCertificates().isEmpty())
                .map(tls -> Response.ok("Hello " + tls.peerCertificates().getFirst().getSubjectX500Principal().getName()))
                .orElseGet(() -> Response.of(StatusCode.FORBIDDEN)))
        .build();
----

WARNING: Always pass trust managers built from your own client CA (or the client certificates you accept). `sslContext.init(keyManagers, null, null)` does not mean "trust nothing": a `null` trust manager array makes JSSE fall back to the JDK default trust store (the public CAs of `cacerts`, or `javax.net.ssl.trustStore`), so `WANT` and `NEED` would then accept any client certificate issued by a public CA.

[cols="1,3"]
|===
| Mode | Behaviour

| `NONE` (default, and what `tls(sslContext)` means)
| No certificate is requested. `peerCertificates()` is empty.

| `WANT`
| A certificate is requested and optional. A client without one is accepted, with an empty `peerCertificates()`; the handler decides what to do. A client that sends a certificate the trust managers reject fails the TLS handshake, as with `NEED`: optional does not mean unchecked.

| `NEED`
| A certificate is required. A client that sends none, or one the trust managers reject, fails the TLS handshake: the client receives the TLS alert (for example `certificate_required`), the connection is closed and no handler runs.
|===

The mode is set per listener and applies at the TLS handshake, for HTTP/1.1 and for HTTP/2 alike. The last `tls(...)` call wins for both the context and the mode: `tls(sslContext)` sets the mode back to `NONE`, and `tls(null)` builds a cleartext server. `NONE` is applied for real: it clears any need or want flag that the engines of a custom `SSLContext` would set.

Chappe never asks for a certificate later in the connection: TLS 1.3 servers in the JDK cannot request one after the handshake, and HTTP/2 forbids TLS 1.2 renegotiation (RFC 9113 §9.2.1). A TLS 1.2 client that tries to renegotiate is disconnected: Chappe closes the connection with a `close_notify`, but sends no alert saying why (no `no_renegotiation` or `handshake_failure`), so the session a handler sees cannot change during the connection. TLS 1.3 KeyUpdate is not a renegotiation and is still supported. If only part of an application needs client certificates, serve it from its own listener in `WANT` or `NEED` mode.

When the server rejects a handshake, it sends the TLS alert that says why, then half-closes and drains what the client still sends for at most 2 s or 1 MiB before closing, so a TCP reset cannot destroy the alert (CHAPPE-027). The handshake itself is bounded by `idleTimeout` (60 s by default), as one total deadline: a client that has not completed its handshake by then is disconnected, whether it sends nothing, half a ClientHello or one byte at a time (CHAPPE-028). A handshake the server rejects still ends with its alert and the bounded linger described above.

A `ClientAuth` other than `NONE` without an `SSLContext` fails at `build()` with an `IllegalArgumentException`.

[.tag-new]#NEW# Client certificates work over TLS 1.2 and TLS 1.3. A TLS 1.2 client sends its certificate, its key exchange and its `Finished` together and then waits for the server: the handshake unwraps everything it has received before it reads the socket again (chappe#24).

[#request-tls]
=== Reading the TLS session in a handler [.tag-new]#NEW#

`Request.tls()` returns the `TlsInfo` of the connection, or `Optional.empty()` on cleartext. It is present exactly when `isSecure()` is `true`:

* `protocol()`: for example `TLSv1.3`.
* `cipherSuite()`: for example `TLS_AES_128_GCM_SHA256`.
* `sessionId()`: a copy of the session id bytes, empty when the session has none.
* `peerCertificates()`: the chain as the client sent it, its own certificate first, then its issuers. A client that sends only its leaf certificate yields a one-element list: the CA the server validated it against is not added. Empty unless the listener asked for one and the client sent it. Always empty under `NONE`.

Chappe reads the session once, when the handshake completes, and every request of the connection sees the same value: HTTP/1.1 keep-alive requests and all HTTP/2 streams.

[#http2]
== HTTP/2

HTTP/2 (RFC 9113) is carried by `chappe-http`: framing, HPACK (RFC 7541) with Huffman coding, flow control, `CONTINUATION` handling, `GOAWAY`/`SETTINGS` lifecycle. The module turns on automatically when TLS + ALPN h2 are configured.

Without TLS, Chappe supports HTTP/2 cleartext (h2c) with **prior knowledge** only: a client that opens the connection with the HTTP/2 preface (`PRI * HTTP/2.0`) is routed straight to the HTTP/2 pipeline; any other cleartext connection is parsed as HTTP/1.1. There is no `Upgrade: h2c` handshake (RFC 9113 deprecated it).

[.tag-new]#NEW# A response's connection-specific fields (`Connection`, `Keep-Alive`, `Proxy-Connection`, `Transfer-Encoding`, `Upgrade`, and `TE` other than `trailers`) are not sent over HTTP/2: RFC 9113 §8.2.2 makes a message carrying one malformed. Chappe leaves them out of the headers and the trailers, and trims leading and trailing spaces and tabs from every value (§8.2.1). Over HTTP/1.1 they are sent as set.

Not supported over HTTP/2:

* **Server push** (RFC 9113 §8.4): Chappe never sends `PUSH_PROMISE`; the client's `SETTINGS_ENABLE_PUSH` is read and has no effect. Browsers no longer accept push, and the Servlet specification deprecates it, so a container on Chappe such as Foy answers `newPushBuilder()` with `null`.
* **`103 Early Hints`** (RFC 8297), on either protocol: a handler sends one final response, and the only informational response Chappe writes is `100 Continue`, on its own, for a request that expects it. To get a resource loaded early, send a `Link: <...>; rel=preload` header on the final response.

== HTTP/3 / QUIC

HTTP/3 (RFC 9114) is **planned**. The QUIC transport is expected to come from the JDK (targeting JDK 26+) — no in-house QUIC engine ships today. See link:{repo-chappe}/blob/main/ROADMAP.md[ROADMAP.md] for the current status.

== Virtual hosts

Chappe does not ship a named "VirtualHost" abstraction — prefer a `Router` that dispatches on `Host`/`:authority`:

[source,java]
----
Handler hostA = Router.builder().get("/", _ -> Response.ok("site A")).build();
Handler hostB = Router.builder().get("/", _ -> Response.ok("site B")).build();

Handler dispatcher = req -> switch (req.header("Host").orElse("")) {
    case "a.example.com" -> hostA.handle(req);
    case "b.example.com" -> hostB.handle(req);
    default -> Response.of(StatusCode.NOT_FOUND);
};

Server.builder().port(8080).handler(dispatcher).build().start();
----

For multi-domain TLS, hand in an `SSLContext` configured with SNI (the JDK picks the certificate via `X509ExtendedKeyManager#chooseEngineServerAlias`).

== Advanced static file serving

Filesystem → classpath fallback chain, in-memory cache, sidecar compression, SPA mode:

[source,java]
----
StaticFileHandler.builder()
    .addPath(Path.of("./public"))                 // 1. filesystem (zero-copy sendfile)
    .addClasspath("static")                        // 2. classpath (jar, module)
    .addClasspath("META-INF/resources")            // 3. webjars / Servlet web fragments
    .cacheInMemory(true)                           // ETag cache for classpath
    .cacheControl("max-age=3600, public")
    .preferPrecompressed(true)                     // .br / .gz sidecars when Accept-Encoding allows
    .spaFallback("/index.html")                    // unknown route → index (SPA)
    .build();
----

Mutually exclusive: `spaFallback(path)` (200 on 404) and `notFoundFile(path)` (404 on 404). Pick one per builder.

== Negotiated compression

The `Filter.gzip()` helper negotiates `Accept-Encoding` and compresses on the fly:

[source,java]
----
Router.builder()
    .filter(Filter.addHeader("X-Content-Type-Options", "nosniff"))
    .filter(Filter.addHeaderIfEnv("STAGING", "true",
            "X-Robots-Tag", "noindex, nofollow"))
    .filter(Filter.gzip())                          // negotiates Accept-Encoding
    .get("/", handler)
    .build();
----

Auto-skip rules:

* the body is below 1 KiB (default threshold);
* the response already carries a `Content-Encoding`;
* `Cache-Control: no-transform` is present;
* the `Content-Type` is not text-like (text/* + application/json + application/xml + application/javascript + +xml + +json).

`AcceptEncoding.parse(header)` and `AcceptEncoding.accepts(header, coding)` expose the RFC 9110 §12.5.3 algorithm (q-values, wildcard, implicit `identity`) — handy for handlers that want to negotiate themselves.

== Mounting a sub-application

`Router#mount(prefix, handler)` delegates **all verbs** to a sub-handler; the prefix is stripped automatically:

[source,java]
----
Router.builder()
    .get("/health", _ -> Response.ok("UP"))           // exact route (priority)
    .mount("/app", servletHandler)                     // e.g. Foy
    .mount("/api", restHandler)                        // e.g. Cassini
    .mount("/static", StaticFileHandler.of(webRoot))
    .notFound(_ -> Response.of(StatusCode.NOT_FOUND))
    .build();
----

Inside the mounted handler:

* `request.path()` is relative to the mount (`/app/index.jsp` arrives as `/index.jsp`),
* `request.contextPath()` returns the prefix (`"/app"`),
* `request.attribute(key, value)` shares attributes with the extension (Servlet-compat).

== Standalone CLI

To serve a static site without an application launcher (typical Docker case):

[source,bash]
----
./mvnw -ntp -pl chappe-cli -am package
java \
     -jar chappe-cli/target/chappe-cli-*-shaded.jar \
     serve --root /var/www/site --port 8080 --gzip
----

Configuration through a YAML file (documented subset: nested maps, lists, scalars, `#` comments; no anchors, no multilines):

[source,yaml]
----
server:
  port: 8080
  bind: 0.0.0.0

static:
  root: /var/www/site
  spa-fallback: /index.html
  cache-control: "max-age=3600, public"
  gzip: true

headers:
  always:
    X-Content-Type-Options: "nosniff"
    Referrer-Policy: "strict-origin-when-cross-origin"
  staging:                       # active when env var STAGING=true
    X-Robots-Tag: "noindex, nofollow"
----

CLI flags override YAML values. See xref:reference.adoc#_chappe_serve_cli[Reference — `chappe serve` CLI] for the full flag list.
